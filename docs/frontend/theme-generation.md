# UI 主题生成

42 套主题的输入在 packages/app/src/lib/theme/all-themes.ts。只保留家族、ID、名称、明暗与 surface/ink/accent/diffAdded/diffRemoved/skill；颜色统一为小写六位 hex。ID 和 Shiki 独立配色保持原有行为。亮暗主题与模式统一保存在 `codex-web-theme-selection`，不带版本号，也不读取或迁移历史存储键；未设置或配置无效时使用默认选择。运行时注册表只暴露 ID、名称和明暗，原始色种子仅用于开发期生成。

## 生成与检查

- `pnpm --filter @codex-web/app themes:generate`：更新应用使用的 `generated-themes.json`。
- `pnpm --filter @codex-web/app themes:check`：重新计算静态色表并验证颜色约束。色表过期或约束失败时退出非零。

开发依赖固定 Leonardo 1.1.0、Color.js 0.7.1。生成器用 Leonardo 的 LCH 完整色阶（1024 采样）承载原始色种子，Color.js 独立测量对比度及 OKLab 色差，从满足所有承载背景约束的候选中选择最接近种子的颜色。没有复制旧曲面公式。Leonardo Theme 的低对比求解在实测深底上有方向不确定问题，因此采用公开 createScale API 和独立约束选择，而非直接信任 Theme 返回。

背景和强调实底保留原值；正文尽可能保留原值。曲面目标为相对背景1.08/1.16/1.24；交互状态针对最高曲面继续向内生成。正文、次要文字、可读强调文字及状态文字在画布、曲面和交互底上至少4.5:1，必要边框和focus至少3:1。实底黑/白前景与全部动作状态分别验收。装饰线与禁用文字不套用正文最低阈值。生成使用4.55/3.05留出量化余量，不等同新的无障碍标准。

成功/危险/警告种子独立为 #30a46c / #e5484d / #f5a524；diff和skill保留自己的种子。阴影和遮罩是明暗共享策略中的显式alpha值。生成结果共有56个语义角色；应用启动仅加载静态JSON并写CSS变量，生成库不进入浏览器运行时。

主题名指现有 App 预设。颜色由当前种子和生成规则决定。新模型仍需要人工观感评估，4.5:1不证明舒适度。后续修改统一角色目标优先于新增主题特例。

## 验收

纯逻辑测试保护42条目、完整角色、背景不变、曲面方向、配对可读性及非法输入。人工回归复用开发入口 /__dev/ui，不新增DOM/截图自动化测试。2026-11-23已在浏览器逐项切换15亮27暗，并查看暖色Solarized和深色Night Owl画面；这不宣称42套在所有场景组合都完成独立视觉验收。
